# 复杂功能模板

用于一个边界明确、需要与实现持续对齐的复杂能力。跨版本迭代时更新原文档。

```markdown
# <功能名称>

## 目标

说明用户或系统最终获得的结果。

## 范围与非目标

- 包含：
- 不包含：

## 当前事实与约束

只记录会实质影响目标设计的现有行为和依赖。

## 目标设计

说明职责划分、状态归属和最小必要组件关系。

## 关键决策

只记录存在可行替代方案、且取舍会影响后续维护的决定与原因；没有则省略。

## 关键流程与状态

只保留容易误解的时序、状态机、异步或并发过程。

## 失败与恢复

只记录会改变方案的失败、降级、重试、幂等、回滚或状态恢复边界；常规错误提示无需罗列。

## 契约与依赖

链接 API、Schema、设计稿或产品资料，只补充这些来源无法表达的业务语义。

## 验收与验证

列出可观察验收条件和对应验证证据。

## 实现对齐

| 关注点 | 稳定代码锚点 | 状态或偏差 |
| --- | --- | --- |

只记录 `planned`、`in-progress`、`complete` 或有意偏离目标的部分。

## 风险与待确认问题

只保留会改变实现或验收的问题，并说明未确认会影响什么、由什么条件或决定解除；没有则省略。
```
