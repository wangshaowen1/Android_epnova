# 审计与归档流程

用于审计、批量收敛或归档现有 docs，不用于单篇文档的普通更新。

## 审计步骤

1. 统计文档数量、目录层级和篇幅，识别版本目录、开发者目录和缺失索引。
2. 将内容归类为项目导览、架构、复杂功能、契约、外部事实源、重复内容或失效内容。
3. 标出代码复述、重复 Schema、实现步骤、版本流水账、失真状态和失效链接。
4. 在移动、合并或删除前给出目标文档地图，说明每份旧文档的去向。
5. 合并仍有效的决策和不变量；可从代码、Schema、需求单或 Git 恢复的细节不迁移。
6. 更新 docs/README.md、相对链接、状态和核验日期。

未要求批量重构时采用触达式迁移；用户明确要求重构指定范围时，按已确认的目标文档地图执行。

## 归档条件

只有失效内容仍能解释重要决策或迁移时才归档。归档说明不保留旧实现教程，控制在 40 行内：

```markdown
# <旧主题>

> 状态：已废弃
> 替代文档：<仓库相对路径>

说明失效原因、仍值得保留的历史决策和当前事实源。
```

没有历史价值的重复内容直接删除；编辑历史由 Git 保存。
