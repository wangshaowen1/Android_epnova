# 📂模块详解
## 1. BaseModule (基础模块层 / Foundation)
**定位**：技术基础设施与架构骨架。
**职责**：1、基础设施：定义 App 的开发规范和基类体、通用的基础设施、工具类；
         2、核心组件：封装第三方SDK封装，提供统一、稳定的技术接口，确保技术栈可替换性。

## 2. Common (通用工具箱 /Shared Toolbox)
**定位**：业务无关的辅助能力，"积木"式可复用组件。
**职责**：为上层模块提供项目通用的生产力工具。

## 3. Core (业务中台层 / Business Kernel)
**定位**：App 的心脏，全 App 共享的业务逻辑与数据。
**职责**：为上层提供统一的数据源、全局状态管理、路由和通用业务逻辑。

## 4. Kit (能力组件层 / Capabilities)
**定位**：独立的、面向特定领域或复杂场景的业务组件。
**职责**：为上层提供特定领域的“黑盒”服务，不关心具体页面展示。

## 5. Feature (业务功能层 / Features)
**定位**：面向用户的业务场景组装。 
**职责**：组装 Core 层的数据和 Kit 层的能力，实现各业务模块具体的页面交互。

## 📂架构层级
| 层级 (Layer) | 模块类型 (Module)          | 依赖关系 (Depends On)  | 职责关键词 (Keywords)                                                                   |
|--------------|--------------------------|----------------------|---------------------------------------------------------------------------------------|
| L4           | Feature (业务层)          | Kit                  | 具体业务场景、完整业务流程、页面与交互实现                                                     |
| L3           | Kit (功能层)              | Core                 | 独立能力封装 (TrackPlayer/TrackListPlayer/TrackDownloader/MusicVideoEditer/MusicChatRoom)|
| L2           | Core (核心层)             | Common               | 全局业务支撑 (User/Config/DB/Network/Router)                                             |
| L1           | Common (通用层)           | BaseModule           | 业务无关工具、UI组件、常量                                                                  |
| L0           | BaseModule (基础模块层)    | SDK/ThirdParty       | 架构基类模块、基础组件模块(图片加载模块/OSS文件上传模块/视频编辑模块/IM模块)                         |

## 📂依赖原则
**向下透明原则** 上层模块可以直接或间接使用所有下层模块的能力。
**向上隔离原则** 下层模块绝对不能感知或依赖任何上层模块。
**横向隔离原则** 同一层级内的模块应保持独立，通过下层或接口进行解耦。


## 📂资源命名
为避免资源冲突，各模块资源文件建议添加前缀：
*   Basic: `base_xxx.xml`
*   Common: `common_xxx.xml`
*   Core: `core_xxx.xml`
*   MusicRoom: `room_xxx.xml`
